## 2. PDM Microphone Interface

### 2.1 PDM Clock

PDM MEMS microphones (e.g. Knowles SPH0645LM4H) require a master clock in the
range 1–3.25 MHz. The PDM clock is derived by dividing the 100 MHz system clock.

```
CLK_DIV = 32  (parameter in pdm_interface.v)
PDM_CLK = SYS_CLK / CLK_DIV = 100 000 000 / 32 = 3 125 000 Hz ≈ 3.125 MHz
```

| Parameter | Value | File / Parameter |
|-----------|-------|-----------------|
| `CLK_DIV` | 32 | `pdm_interface.v` → `CLK_DIV` |
| PDM clock output | 3.125 MHz | within datasheet range |
| PDM clock duty cycle | 50 % | toggle every CLK_DIV/2 = 16 sys-cycles |

The PDM clock is generated by a simple counter in `pdm_interface.v`. PDM data
is captured on the **rising edge** of the PDM clock, as required by SPH0645LM4H
(L/R selection pin ties the mic to the rising or falling edge; this design uses
rising-edge mics).

### 2.2 Microphone Array Geometry

| Parameter | Value | Justification |
|-----------|-------|---------------|
| Number of microphones | 4 | Four Pmod JA data pins available |
| Array topology | Linear (ULA) | Simplest beamforming geometry |
| Inter-element spacing `d` | 10 mm | Half-wavelength at 17.15 kHz ≈ λ/2, safe up to ~17 kHz |
| Physical orientation | Perpendicular to target axis | Standard end-fire / broadside convention |

## 3. CIC Decimation Filter

### 3.1 Filter Parameters

The CIC filter converts the 1-bit PDM stream to a multi-bit PCM sample.

| Parameter | Symbol | Value | File / Parameter |
|-----------|--------|-------|-----------------|
| Filter order | N | 4 | `cic_filter.v` → `ORDER` |
| Decimation ratio | R | 64 | `cic_filter.v` → `DEC_RATIO` |
| Input bit-width | — | 1 bit | `cic_filter.v` → `INP_WIDTH` |
| Internal accumulator | — | 36 bits | `cic_filter.v` → `ACC_WIDTH` |
| Output bit-width | — | 16 bits | `cic_filter.v` → `OUT_WIDTH` |

### 3.2 Output (PCM) Sample Rate

```
PCM_RATE = PDM_CLK / DEC_RATIO = 3 125 000 / 64 = 48 828.125 Hz ≈ 48 828 Hz
```

Used as `SAMPLE_RATE_HZ = 48828` in `beamform.h` and `main.c`.

### 3.3 Gain and Bit Growth

For a CIC filter of order N with decimation ratio R, the DC gain is:

```
G = R^N = 64^4 = 16 777 216
```

Required internal width to avoid overflow with a 1-bit (±1) input:

```
W_full = INP_WIDTH + N * ceil(log2(R))
       = 1 + 4 * ceil(log2(64))
       = 1 + 4 * 6
       = 25 bits
```

`ACC_WIDTH = 36` is chosen with a 11-bit margin to prevent overflow for any
practical input pattern while keeping the design wide enough for synthesis into
DSP48 slices.

Output truncation: the top `OUT_WIDTH = 16` bits of the 36-bit accumulator are
used. Bits `[35:20]` are taken, discarding 11 guard bits above and 20 noise
bits below.

```
data_out = comb_final[ACC_WIDTH-1 -: OUT_WIDTH]   // bits [35:20]
```

This provides approximately 16-bit dynamic range with a small implicit shift.

### 3.4 CIC Frequency Response Droop

The CIC filter has a sinc^N passband droop. At the Nyquist frequency of the
output (24.4 kHz):

```
f_norm = 24414 / 3125000 = 0.00781 (normalised to PDM rate)
Droop = |sin(π * f_norm * R) / (R * sin(π * f_norm))|^N
      = |sin(π * 0.5) / (64 * sin(π * 0.00781))|^4
      ≈ |1 / (64 * 0.02454)|^4
      ≈ |0.636|^4
      ≈ -3.9 dB at Nyquist
```

For audio speech (< 4 kHz), droop is < 0.5 dB — acceptable without
compensation filtering.

## 4. Beamformer

### 4.1 Delay-and-Sum Parameters

| Symbol | Value | Source |
|--------|-------|--------|
| `NUM_CHANNELS` | 4 | Number of microphones |
| `DATA_WIDTH` | 16 | CIC output width |
| `MAX_DELAY` | 32 | Maximum delay line length (taps) |
| `OUT_WIDTH` | 18 | 16 + log2(4) = 18 bits (to hold sum of 4 channels) |

### 4.2 Delay Calculation

For a ULA with steering angle θ (broadside = 0°), the delay for channel m is:

```
Δm = (m × d × sin θ) / (c × (1/fs))
   = (m × d × sin θ × fs) / c
```

Where:
- `m` = channel index (0, 1, 2, 3)
- `d` = 0.010 m (10 mm spacing)
- `c` = 343 m/s (speed of sound at 20°C, 50% RH)
- `fs` = 48 828 Hz (PCM sample rate)

For maximum steering angle (θ = 90°, end-fire):

```
Δ_max = (3 × 0.010 × 1.0 × 48828) / 343 = 4.27 samples
```

The `MAX_DELAY = 32` taps provides large margin for non-standard array
geometries (e.g. 25 mm spacing → ~10.7 samples, or angled mounting).

### 4.3 Firmware Angle Encoding

Angles are passed from the host as tenths-of-degrees (e.g. 300 = 30.0°).
The firmware in `beamform.h` uses a linear sin approximation:

```
sin(θ) ≈ θ_rad × (1 - θ_rad²/6)   [Taylor, valid for |θ| < 30°]
```

Simplified for integer arithmetic (Q0.3 approximation):

```
sin_val = angle_tenths × 17 / 1000
```

Derivation: π/180/10 ≈ 0.01745/10 = 0.001745; scaled by ~10 gives ~0.01745,
multiplied by 1000 gives 17.45 → rounded to 17.  Error < 3% for θ ≤ 60°.

The resulting delay in samples:

```
delay_ch = ch × MIC_SPACING_UM × sin_val × SAMPLE_RATE_HZ
           / (SPEED_OF_SOUND × 1_000_000)
```

Where `MIC_SPACING_UM = 10000` (10 mm in µm), `SPEED_OF_SOUND = 343`.

## 5. FFT Engine

### 5.1 Configuration

| Parameter | Value | File |
|-----------|-------|------|
| FFT size N | 256 | `fft_engine.v` → `FFT_SIZE`, `fft_ctrl.h` → `FFT_N` |
| Data width | 16 bits | `fft_engine.v` → `DATA_WIDTH` |
| Algorithm | Radix-2 DIT (Decimation-In-Time) | — |
| Number of stages | log2(256) = 8 | — |
| Number of butterflies per stage | N/2 = 128 | — |
| Total butterflies | 8 × 128 = 1024 | — |
| Twiddle format | Q1.15 fixed-point | `twiddle_rom.v` |

### 5.2 Frequency Resolution

```
Δf = fs / N = 48828 / 256 ≈ 190.7 Hz
```

Frequency of bin k:

```
f(k) = k × Δf = k × 190.7 Hz
```

Useful range: bins 1 – 127 (positive frequencies, 190 Hz – 24.2 kHz).

In firmware (`main.c`):

```c
peak_freq_hz = peak_bin * 48828 / FFT_N;   // = peak_bin * 190.7
```

### 5.3 Twiddle Factor ROM

Twiddle factors W_N^k = cos(2πk/N) − j·sin(2πk/N) in Q1.15 format:

```
W_real[k] = round(cos(−2π·k / 256) × 32767)
W_imag[k] = round(sin(−2π·k / 256) × 32767)
```

The ROM uses `$cos` and `$sin` system functions in an `initial` block (synthesises
to a Xilinx BRAM or LUT ROM). 128 entries (N/2) are stored; by FFT symmetry
this covers all stages.

Twiddle ROM address for butterfly at stage `s`, butterfly index `b`:

```
tw_addr = (b % (1 << s)) × (N / (1 << (s+1)))
```

### 5.4 Fixed-Point Butterfly Scaling

Complex multiply of Q1.15 values produces Q2.30 intermediate. The result is
right-shifted by `DATA_WIDTH − 1 = 15` to return to Q1.15:

```verilog
wb_real = (mult_br_wr - mult_bi_wi) >>> (DATA_WIDTH - 1);
```

After each butterfly stage the signal may grow by 1 bit. With 8 stages the
maximum growth is 8 bits; the 16-bit data path can overflow for large inputs.
In practice, audio signals have crest factor ≈ 12 dB, so 2–3 guard bits
suffice. For worst-case impulse signals, the firmware should scale input or use
block floating-point.

### 5.5 Input Bit-Reverse Order

The DIT FFT requires bit-reversed input ordering. The `bit_reverse` function
in `fft_engine.v` permutes the load address:

```
bit_reverse(k, log2(N=256)) reverses the 8 LSBs of k
Example: k=1 (0b00000001) → 0b10000000 = 128
         k=2 (0b00000010) → 0b01000000 = 64
```

### 5.6 Wishbone Register Map (FFT Engine)

| Offset | Name | Direction | Description |
|--------|------|-----------|-------------|
| 0x000 | `FFT_CTRL` | W | bit0=start_load, bit1=re-arm to IDLE |
| 0x004 | `FFT_STATUS` | R | bit0=busy, bit1=done |
| 0x100 + k×4 | `FFT_REAL[k]` | R | Real part of bin k (sign-extended to 32 b) |
| 0x300 + k×4 | `FFT_IMAG[k]` | R | Imag part of bin k (sign-extended to 32 b) |

## 6. Laser Vibrometer

### 6.1 SPI ADC Interface

The external ADC (e.g. Digilent Pmod AD1 / AD7476A, or MCP3202) is driven by
`spi_master.v` instantiated inside `laser_vibrometer.v`.

| Parameter | Value | File |
|-----------|-------|------|
| SPI word width | 16 bits | `spi_master.v` → `WIDTH` |
| SPI mode | CPOL=0, CPHA=0 (Mode 0) | `spi_master.v` |
| SPI clock divider | 8 | `laser_vibrometer.v` instantiation |
| SPI clock frequency | 100 MHz / (2×8) = 6.25 MHz | within ADC spec |

ADC sample rate is set by `SAMPLE_RATE = 48000` Hz in `laser_vibrometer.v`:

```
SAMPLE_DIV = 100_000_000 / 48000 ≈ 2083 sys-clock cycles between conversions
```

Two SPI transactions per sample cycle: one for I channel, one for Q channel.

### 6.2 Quadrature Demodulation

The laser interferometer produces in-phase (I) and quadrature (Q) electrical
signals proportional to the target surface displacement φ(t):

```
I(t) = A·cos(φ(t))
Q(t) = A·sin(φ(t))
```

Instantaneous phase change (proportional to velocity) is computed using the
cross-product discriminator:

```
Δφ[n] = I[n−1]·Q[n] − Q[n−1]·I[n]
```

This avoids `arctan` and is exact when `|Δφ| ≪ 1 rad` per sample period.  For
acoustic vibration (< 10 kHz) and sample rate 48 kHz, the maximum phase step is:

```
|Δφ_max| = 2π × 10000 / 48000 ≈ 1.31 rad
```

At large phase steps the cross-product approximation loses accuracy
(> ~10% error beyond 0.5 rad). For high-velocity measurements a true `atan2`
look-up or CORDIC should replace this; for audio applications (< 4 kHz,
< 0.5 rad/sample) the approximation is adequate.

### 6.3 Velocity Scaling

The hardware outputs a fixed-point velocity proportional to Δφ:

```verilog
velocity_out = phase_diff[DATA_WIDTH+7 : 8];   // bits [23:8] of 32-bit product
```

For a HeNe laser (λ = 632.8 nm):

```
v(t) = (λ / 4π) × dφ/dt
     = (632.8×10⁻⁹ / 4π) × (Δφ × fs)
     ≈ 50.3 nm/rad × 48000 rad/s (per LSB of Δφ)
```

The velocity LSB depends on the ADC full-scale (V_FS) and the optical setup;
firmware applies a calibration factor if needed.

### 6.4 Wishbone Register Map (Laser Vibrometer)

|--------|------|-----------|-------------|
| 0x00 | `LASER_CTRL` | R/W | bit0=enable acquisition |
| 0x04 | `LASER_STATUS` | R | bit0=data_valid (new sample ready) |

| 0x0C | `LASER_Q_SAMPLE` | R | Last Q ADC sample (sign-extended 32 b) |

## 7. RISC-V Core

### 7.1 Architecture

| Parameter | Value |
|-----------|-------|
| ISA | RISC-V RV32I (32-bit integer base) |
| Pipeline stages | 3 (Fetch → Execute → Memory/Writeback) |
| Reset address | `0x0000_0000` (start of Block RAM) |
| Register file | 32 × 32-bit (x0 hardwired to 0) |
| Bus interface | Wishbone B4 (separate instruction + data) |

### 7.2 Instruction Set Coverage

All 40 base RV32I instructions are implemented:
- Integer arithmetic: ADD, SUB, ADDI, AND, OR, XOR, ANDI, ORI, XORI
- Shifts: SLL, SRL, SRA, SLLI, SRLI, SRAI
- Comparisons: SLT, SLTU, SLTI, SLTIU
- Loads: LB, LH, LW, LBU, LHU
- Stores: SB, SH, SW
- Branches: BEQ, BNE, BLT, BGE, BLTU, BGEU
- Jumps: JAL, JALR
- Upper immediates: LUI, AUIPC
- System: FENCE (NOP), ECALL/EBREAK (NOP), CSR (NOP)

M-extension (MUL/DIV) is **not** implemented; software multiplication is used
in the beamformer delay calculation.

### 7.3 Performance

Assuming 1 CPI average (no cache misses for BRAM), peak throughput = 100 MIPS.
With Wishbone acknowledge latency of 1 cycle per access, effective CPI ≈ 3–4
(fetch + execute + memory).  At 100 MHz this gives ~25–33 M effective
instructions/second — more than sufficient for the control tasks in `main.c`.

### 7.4 Memory Map

| Base Address | Size | Peripheral |
|--------------|------|-----------|
| `0x0000_0000` | 8 KB | Block RAM (instruction + data) |
| `0x8000_0000` | 16 B | GPIO |
| `0x8000_1000` | 8 B | UART TX |
| `0x8000_2000` | 8 B | UART RX |
| `0x8000_3000` | 16 B | Beamformer delay registers |
| `0x8000_4000` | 4 KB | FFT Engine (control + result) |
| `0x8000_5000` | 20 B | Laser Vibrometer |

Address decode in `wishbone_interconnect.v`:
- Bit 31 = 0 → Slave 0 (RAM)
- Bit 31 = 1, bits [15:12] = 0x0 → GPIO
- Bit 31 = 1, bits [15:12] = 0x1 → UART TX
- …etc.

## 13. Timing Budget

At 100 MHz (10 ns period):
- CIC integrators: combinational path ≈ 2–3 ns (simple adder chain)
- Beamformer sum: combinational path ≈ 3–4 ns (4-input adder tree)
- FFT butterfly: 2-stage pipeline; each stage ≈ 4–5 ns (DSP48E1 multiply)
- RISC-V execute stage: longest path ≈ 6–7 ns (ALU + register read)

Estimated setup slack > 1 ns for all paths at 100 MHz with Artix-7 speed
grade -1.  If timing fails at 100 MHz, reduce to 80 MHz using the Clocking
Wizard IP.
